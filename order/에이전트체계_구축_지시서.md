# CC 작업 지시서 — 개발 에이전트 체계 구축

> 위치: `AI_First_Step/order/에이전트체계_구축_지시서.md` · **AI_First_Step에서 실행** 후, 산출물을 본진(AX_Lecture)에도 복사(공유 규범 — 엔진_경계.md 원칙).
> 목적: 강의 준비→수업→반복학습→지속 관리로 커진 이 프로젝트에, **역할이 정의된 개발 에이전트 5종**을 상설한다.
> 설계 원칙 = 우리 8강 그대로: 각 에이전트는 "무엇을 보고 · 어떤 도구로 · 어디서 멈추고 · 누가 확인하는지"가 명시된다. **모든 에이전트는 보고까지만 — 수정은 사람 승인 후 별도 실행.**
> 권장 모델: 높음.

## 구조 개요

```
[운영 에이전트 — 제품 안, 기존]  AI 주간 브리핑 (+향후 RAG 조교·AI 처방전)
[개발 에이전트 — 오늘 구축]      .claude/agents/ 서브에이전트 5종
```

| 에이전트 | 역할 한 줄 | 주 호출 시점 |
|---|---|---|
| persona-reviewer | 수강자 페르소나 눈으로 콘텐츠 검증 | 상자 콘텐츠 완성 직후 |
| tone-keeper | 톤앤매너·규격 일관성 감사 | 콘텐츠 완성 직후 / 주기 감사 |
| qa-runner | 기능 회귀 검증 일괄 실행 | 모든 구현 작업 후 |
| boundary-keeper | 엔진/콘텐츠 경계·백포트 감시 | diff 발생 시 / 병합 전 |
| release-manager | 병합·태그·인계 절차 집행 | 마일스톤 마감 시 |

## 작업 순서

1. **`docs/톤앤매너.md` 신설** (tone-keeper의 헌법 — 아래 A).
2. **`.claude/agents/` 폴더에 에이전트 정의 5종** 생성 (아래 B — 정의문 그대로, 실제 서브에이전트 형식 규격은 CC가 현행 Claude Code 문서 기준으로 맞출 것).
3. **첫 가동 검증** (아래 C).
4. **`docs/에이전트_운영.md`** — 호출법·역할표·"보고만, 수정은 승인 후" 원칙 기록.
5. 커밋 후, `.claude/agents/`·`docs/톤앤매너.md`·`docs/에이전트_운영.md`를 **본진에도 복사·커밋** (본진 톤앤매너는 AX용 차이를 반영해 조정 — 아래 A 참고).

## A. docs/톤앤매너.md (첫걸음판)

기존 콘텐츠(로비)와 지시서들의 규칙을 헌법화. 최소 포함:

- **규격**: 강당 12~14장 · 필수 요소(사례·흔한 오해 셋·생각해보기·한 장 정리+과제) · 티저 체인 · big/quote는 핵심훑기 자산
- **어투**: 두려움 제거 우선, 부드러운 존대, 가벼운 유머 허용, 위협·훈계 금지
- **용어**: 05강의 10개 외 신규 용어는 즉시 한 줄 풀이 동반, 영문 약어 남발 금지
- **페르소나**: 화자 김주임(기본)·박선배(대학생)·최사장(자영업) — `[P]` 태그 슬라이드만 페르소나 분화, 개념·도식·big/quote는 공유
- **도식**: E 시리즈 라이트 톤(아이보리+청록/마젠타/보라), 다크 스킨에서 카드형 처리
- **금지**: 특정 제품 서열화, 공포 마케팅, 근거 없는 수치
- (본진 복사본은 AX 차이를 반영: 15~17장 규격·D 시리즈 다크 도식·실무자 어투·"사람이 방향 AI가 초안" 관통 문장)

## B. 에이전트 정의 5종 (.claude/agents/)

> 각 정의는 아래 내용을 시스템 프롬프트로 담는다. 공통 머리말(전 에이전트 포함):
> "너의 산출물은 **보고서뿐**이다. 파일을 수정하지 않는다. 발견 사항은 심각도(높음/중간/낮음)와 위치(강·슬라이드)를 붙여 보고하고, 수정 제안은 '제안' 섹션에 분리한다. 판단이 애매하면 애매하다고 말한다."

### 1) persona-reviewer.md — 페르소나 검증

- **보는 것**: 지정된 강의 범위의 data.js 콘텐츠 (+`[P]` 태그 슬라이드 중점)
- **도구**: 파일 읽기, docs/톤앤매너.md·페르소나_작성_가이드.md 참조
- **역할**: 지정 페르소나(기본: 김주임=주니어 직장인 / student=박선배 / owner=최사장)의 눈으로 통독하고 검증 —
  ① 위화감: 이 페르소나가 "내 얘기 아닌데"라고 느낄 예시·상황
  ② 난이도: 설명 없이 등장한 개념·용어 (05강 10개 + 기수강 내용 외)
  ③ 과제 실행 가능성: 이 페르소나가 오늘 실제로 할 수 있는가
  ④ 서사 연속성: 화자 성장선·앞 강의 회수가 어긋난 곳
- **멈추는 곳**: 강·슬라이드 단위 발견 목록 + 페르소나별 총평 3줄 보고. **문구를 고치지 않는다.**
- **사람 확인**: 보고를 보고 수정 여부·범위는 사용자가 결정

### 2) tone-keeper.md — 톤앤매너 감사

- **보는 것**: 지정 범위 콘텐츠 (신규 상자 또는 전체 주기 감사)
- **도구**: docs/톤앤매너.md (헌법 — 이 문서와 다르면 문서가 이긴다)
- **역할**: 규격 준수(필수 요소·장수 범위·티저 체인), 어투 일탈(훈계·위협·과장), 용어 규칙, 도식 톤, 금지 사항을 조문 대조로 감사. **일관성 편차**(같은 요소가 강마다 다르게 처리된 곳)를 특히 잡는다.
- **멈추는 곳**: 조문별 위반/편차 목록 + "헌법이 낡았다면 개정 제안" 섹션(문서 vs 실제 충돌 시 어느 쪽이 맞는지 의견). 수정 없음.
- **사람 확인**: 위반 수정이든 헌법 개정이든 사용자 결정

### 3) qa-runner.md — 기능 회귀 검증

- **보는 것**: 로컬 구동 상태(netlify dev)·콘솔·DOM·(가능하면) Supabase
- **도구**: 서버 실행, 브라우저 검사, 네트워크 조회
- **역할**: 표준 회귀 세트를 일괄 실행 —
  렌더(신규+표본 강의) · 티저 체인 · 이어보기 · 핵심훑기 · 스킨 전수 · 375px 오버플로 · 콘솔 0 · (해당 시) 텔레메트리 insert→정리 · variant/`?join=`/`#/admin` 표본 · 키 비노출
- **멈추는 곳**: 항목별 ✅/⚠️/❌ 표 + 재현 절차. **발견 버그를 즉석 수정하지 않는다**(재현 정보만).
- **사람 확인**: ❌ 항목의 수정 지시는 사용자(또는 사용자가 승인한 후속 작업)

### 4) boundary-keeper.md — 엔진 경계·백포트 감시

- **보는 것**: 작업 diff(커밋 전후), docs/엔진_경계.md
- **도구**: git diff, 파일 읽기
- **역할**: ① 이번 변경이 공유 엔진/사이트 고유 중 어디를 건드렸는지 분류 ② 엔진 변경이면 **백포트 대상 후보**로 표기(양방향: 첫걸음→본진, 본진→첫걸음) ③ 경계 침범(콘텐츠 작업이 엔진을 슬쩍 고친 경우) 적발 ④ 이식 이력 기록 누락 확인
- **멈추는 곳**: 분류표 + 백포트 후보 목록 + 이력 기록 문안 제안. 이식 실행은 하지 않는다.
- **사람 확인**: 백포트 실행 여부·시점은 사용자

### 5) release-manager.md — 마일스톤 마감

- **보는 것**: 브랜치 상태, 완료된 작업 범위, 기존 태그 체계
- **도구**: git, qa-runner 호출(마감 전 회귀), boundary-keeper 호출(경계 확인)
- **역할**: 마감 절차 집행 — 병합 전 점검(미커밋·충돌 예측) → qa-runner 회귀 → 병합 → 태그 명명(기존 체계 연속: v1.x-이름) → push 1회 → 인계 상태(테이블 0건 등) 확인 → 마감 보고
- **멈추는 곳**: **병합·태그·push 실행 전에 계획을 요약 보고하고 사용자 승인을 받는다** (이 에이전트만 실행 권한이 있으나, 실행 직전 확인 게이트 필수 — 17강 원칙)
- **사람 확인**: 병합 실행 승인

## C. 첫 가동 검증

- [ ] **persona-reviewer**를 `로비(01~05)` × 김주임 관점으로 1회 가동 → 보고서가 강·슬라이드 단위 발견 + 총평 형식으로 나오는지. (보고서는 `order/검증리포트_로비_persona.md`로 저장)
- [ ] **tone-keeper**를 로비에 1회 가동 → 헌법 조문 대조 형식 확인. (동일하게 저장)
- [ ] **qa-runner** 1회 가동 → 표 형식 보고 확인.
- [ ] **boundary-keeper**를 최근 커밋(로비 콘텐츠)에 가동 → "콘텐츠 전용, 엔진 무변경" 분류가 정확히 나오는지.
- [ ] release-manager는 정의만 검증(모의 계획 보고까지, 실제 병합 없음).
- [ ] 각 에이전트가 **파일을 수정하지 않았는지** git status로 확인.

## D. docs/에이전트_운영.md

- 역할표(위 표) · 호출 예시("로비를 persona-reviewer로 student 관점 검증해줘") · 표준 파이프라인:
```
콘텐츠 완성 → persona-reviewer + tone-keeper → (사람: 수정 결정) → 수정 →
qa-runner → boundary-keeper → (사람: 승인) → release-manager 마감
```
- 원칙 명문화: 에이전트는 보고만 / 수정·병합은 사람 승인 후 / 보고서는 order/에 저장.
