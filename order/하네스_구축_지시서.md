## 기술 방침

- **의존성 0**: Node 내장 test runner(`node --test`) 사용. 외부 프레임워크 설치 금지(정적 프로젝트 유지).
- `package.json` 없으면 최소로 생성(`"test": "node --test tests/"`, private, deps 없음).
- **CI 없음** — 로컬 실행 전용(배포 크레딧 정책과 무관하게 유지). 실행법은 문서화.
- data.js가 브라우저 전역 방식이라 Node에서 못 읽으면: **브라우저 동작에 0 영향**인 최소 export 심(예: `typeof module !== 'undefined'` 가드) 추가 허용 — 단, 엔진 파일 수정이므로 boundary-keeper 관점에서 백포트 대상으로 보고.

## 구성 3종 (tests/)

### 1) 콘텐츠 무결성 린트 — `tests/content-lint.test.js` (최우선)

data.js 전체를 검사:
- 강의 수 = 20, 각 강 slides 비어있지 않음
- 첫 슬라이드 = cover, 마지막 = closing
- 슬라이드 type이 유효 집합(cover/big/bullets/quote/split/image/closing + 실제 스키마에 있는 것) 내
- 각 타입의 필수 필드 존재(bullets.items 배열, split.left/right, image.src 등)
- **image의 src 파일이 assets/에 실존**
- closing에 teaser 존재(마지막 강 제외 규칙은 사이트별 — 첫걸음 20강은 AX 티저가 있으므로 존재)
- slidesVariants(있으면): 오버라이드 키(인덱스 또는 id)가 기본판의 유효 위치를 가리킴, 오버라이드 슬라이드도 타입·필수 필드 유효
- 린트 상수(강의 수·타입 집합 등)는 파일 상단에 모아 **사이트별 조정이 쉽게**

### 2) 집계 단위 테스트 — `tests/aggregate.test.js`

`netlify/functions/_shared/aggregate.js` 대상. 고정 픽스처(가짜 이벤트 배열)로:
- 코드별 completedLectures 유니크 집계, lastSeen 최신값
- diagnosis/checkup은 **최신 결과만** 반영(재검사 갱신)
- lectureCompletion 인원 집계, diagnosisAverages·checkupAverage 수치(수기 계산값과 일치)
- `class`(접두어)·`course` 필터 정확성(교차 포함)
- 빈 배열(0명) 시 안전한 기본 구조 반환

### 3) 함수 계약 테스트 — `tests/functions-contract.test.js`

핸들러를 **직접 import·호출**(네트워크 없음, `global.fetch`는 스텁으로 대체해 Supabase/AI 호출 차단):
- track: GET→405 · 미등록 event_type→400 · 8KB 초과→413 · 코드 길이 위반→400 · 정상 POST→204(스텁 insert 호출 확인) · course 검증
- stats/brief: 키 없음/불일치→401 · 정상 키→스텁 데이터 기반 정상 응답
- brief: 0명 시 **AI 스텁이 호출되지 않음**(결정론적 방어의 회귀 테스트化)

## 작업 순서

1. package.json·tests/ 3종 작성 → `npm test` 전체 통과 확인.
   - **기존 콘텐츠가 린트에 걸리면 콘텐츠를 고치지 말 것** — 규칙이 과한지/콘텐츠 문제인지 발견 목록으로 보고(사람 결정). 통과 불가 규칙은 임시 warning 처리하고 표기.
2. **탐지력 검증**: 저장소 밖 임시 사본(/tmp 등)에 고의 결함(타입 오타·src 오타·티저 삭제) 3건 심고 린트가 전부 잡는지 확인 — 저장소는 건드리지 않는다.
3. **qa-runner 등록**: 정의문 1단계에 "`npm test` 실행, 실패 항목 보고" 추가. `docs/에이전트_운영.md`에 하네스 항목(실행법·범위·"하네스=결정론, 에이전트=판단" 구분) 추가.
4. 커밋 후 **본진 적용**: 동일 구성 복사 + 사이트별 조정(린트 상수, slidesPersonal/variants 구조 반영, D 시리즈 도식 경로) → 본진 `npm test` 통과 확인 → 본진 커밋. export 심을 본진 엔진에도 넣게 되면 이식 이력 기록.

## 가드레일

- 콘텐츠·집계 로직·함수 로직 수정 금지 — 테스트가 실패하면 그것이 발견이다(보고).
