# CC 작업 지시서 — 연습 책상 레이아웃 수정 + 시각 검증 체계 수립

> 위치: `AI_First_Step/order/시각검증체계_지시서.md` · **AI_First_Step에서 실행**(③④는 양쪽).
> 배경: 연습 책상이 기능 검증은 통과했으나 **화면 배치가 깨진 채** 완료 보고됨(헤더가 좌측 허공, 카드가 우측 좁은 기둥, 화면 절반 공백). 원인 = qa-runner가 DOM·콘솔 검증만 하고 **시각 검증 없이 통과 처리**하는 구조적 공백.
> 권장 모델: 엑스트라(레이아웃 원인 진단 포함).

---

## ① 연습 책상 레이아웃 수정 (즉시)

**증상**(사용자 스크린샷 기준, 데스크톱 와이드):
- "연습 책상" 헤더·진행률이 화면 좌측 세로 중앙에 고립되어 떠 있음
- 미션 카드들이 우측 절반의 좁은 컬럼에 몰림
- 좌측 대부분이 빈 공간

**요구 상태**:
- 헤더(제목·부제·미션 진행률·← 입장 화면)는 **상단 가로 배치**, 콘텐츠는 그 아래 **중앙 정렬 단일 컬럼**(최대폭 ~900px 수준, 카드 그리드는 폭에 따라 1~3열 반응형)
- 3존 전환 탭(스탬프판/조립대/키트)이 헤더 아래 명확히
- 375px(1열) → 태블릿(2열) → 데스크톱(2~3열) 자연 반응형
- 진단실(#practice 씬)의 레이아웃 문법과 유사한 수준의 정돈

**원인 진단을 먼저 보고**(수정 전): 어떤 CSS/구조가 이 배치를 만들었는지 — 같은 실수 재발 방지용.

## ② 시각 검증 프로토콜 — qa-runner 정의 개정 (양쪽)

`.claude/agents/qa-runner.md`에 다음 절차를 **필수 단계**로 추가:

> **시각 검증 (필수)**
> 1. 화면이 새로 생기거나 레이아웃이 변한 작업은, 대상 화면을 **3개 뷰포트(375 / 768 / 1440px)에서 스크린샷 캡처**하고 **직접 열어 확인**한다.
> 2. 확인 기준(각 뷰포트): 주요 영역의 배치가 의도와 일치 / 큰 공백·쏠림 없음 / 헤더·콘텐츠·내비의 위계가 시각적으로 성립 / 텍스트·버튼 겹침 없음.
> 3. 스크린샷은 `order/스크린샷_{작업명}/`에 저장하고, 검증 보고서에 파일 경로를 명시한다.
> 4. **캡처가 실패(타임아웃 등)하면 대체 검증(DOM)으로 통과 처리하지 않는다.** 보고서 최상단에 `⚠ 시각 검증 미수행 — 사용자 육안 확인 필요` 플래그를 달고, 완료 보고에도 동일 문구를 반드시 포함한다. (대체 검증은 "보조"이지 "동급"이 아니다.)

- `docs/에이전트_운영.md` 표준 파이프라인에 시각 검증 단계 반영.
- `docs/UX_원칙.md` 점검 체크리스트에 "3뷰포트 스크린샷 확인" 항목 추가.
- 이 개정은 공유 규범 — **양쪽 저장소 동기화 + §7 기록.**

## ③ 하네스 — 기하 스모크 테스트 (경량, 선택적 보강)

시각 검증의 기계적 보조선. `tests/`에 추가(과하지 않게, 핵심 2~3개만):
- 주요 씬 컨테이너의 렌더 폭이 뷰포트의 일정 비율(예: 데스크톱에서 콘텐츠 영역 ≥ 50%) 이상인지
- 헤더 요소가 뷰포트 상단 영역(예: y < 200px)에 위치하는지
- 구현 방식은 CC 판단(jsdom 한계 시 실브라우저 필요 여부 보고 — 불가하면 이 항목은 qa-runner 시각 검증으로 갈음하고 사유 기록).

## ④ 소급 시각 점검 (한 번)

새 프로토콜의 첫 적용으로, **양 사이트 주요 화면을 3뷰포트 스크린샷으로 일괄 점검**:
- AX: 입장 화면 / 사유의 방 / 강의(1개) / 진단실 3층 / #/admin
- 첫걸음: 입장 화면 / 방 / 강의(1개) / 연습 책상 3존(①수정 후)
- 발견된 배치 문제는 **보고만**(연습 책상 외 수정 금지) — 목록화해 사용자 결정.
