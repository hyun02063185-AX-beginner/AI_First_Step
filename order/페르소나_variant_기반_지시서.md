# CC 작업 지시서 — 페르소나 variant 기반 구축

> 위치: `AI_First_Step/order/페르소나_variant_기반_지시서.md` · **AI_First_Step에서 실행.**
> 목적: 「첫 출근」을 직장인판(기본) 외에 대학생·자영업자 등 **페르소나별 사이드 버전**으로 확장할 수 있는 엔진 기반을 만든다. **이번엔 기반만** — 실제 페르소나 콘텐츠는 20강 완성 후.
> 이 확장은 **본진(AX) 이식 대상** — slidesPersonal의 상위 호환. 권장 모델: 높음.

---

## 설계 원칙

1. **부분 오버라이드 상속** — 페르소나판은 "바뀐 슬라이드만" 갖는다. 나머지는 기본판 상속. 기본판을 고치면 모든 페르소나에 자동 반영(유지보수 N배 방지).
2. **개념·도식은 공유, 사례·과제만 교체** — 페르소나가 갈아끼우는 대상은 원칙적으로 사례/생각해보기/과제 슬라이드.
3. 기존 `?variant=` URL 방식·세션 유지·뱃지 관례를 계승.

## ① 데이터 구조 (js/data.js)

```js
// 강의 객체 — 개념 (실제 스키마 관례에 맞출 것)
lecture01: {
  ...,
  slides: [ /* 기본판(직장인) — 항상 완전한 정본 */ ],
  slidesVariants: {
    // 페르소나키: { 오버라이드맵 }  — 슬라이드 "인덱스" 기준 부분 교체
    student: { 6: {...김주임→박선배 사례...}, 10: {...}, 11: {...} },
    owner:   { 6: {...}, 11: {...} }
  }
}
```

- **오버라이드 단위 = 슬라이드 인덱스**(0-base). 값은 완전한 슬라이드 객체(타입 변경도 허용).
- 인덱스 방식의 취약점(기본판 슬라이드 삽입 시 인덱스 밀림)을 문서에 명시하고, 대안으로 **슬라이드에 선택적 `id` 부여 + id 기준 오버라이드**를 지원할 수 있으면 그쪽을 우선(CC가 엔진 부담 판단해 택1, 선택 근거 보고). 어느 쪽이든 규칙을 ③ 가이드에 못박는다.
- 슬라이드 **추가/삭제**는 1차 범위 외(교체만) — 필요성이 생기면 그때 확장.

## ② 전환 로직 (엔진)

- `?variant=student` → 전역 페르소나 플래그(세션 유지, 기존 방식). 렌더 시 `slidesVariants[페르소나]`가 있으면 해당 인덱스/ID만 교체해 합성.
- 등록되지 않은 variant 값 → 조용히 기본판(오류 없음).
- site-config에 페르소나 레지스트리:
```js
personas: {
  default: { label: '직장인', badge: null },
  student: { label: '대학생', badge: 'S' },
  owner:   { label: '자영업', badge: 'O' }
}
```
- 활성 페르소나가 default가 아니면 HUD에 작은 뱃지(기존 P 뱃지 관례). 텔레메트리 이벤트에 `variant` 필드 추가(있을 때만) — 나중에 "어느 판 수강생인지" 대시보드에서 구분 가능하게(track 화이트리스트/스키마 영향 확인, payload에 넣는 최소 방식 권장).

## ③ docs/페르소나_작성_가이드.md 신설

콘텐츠 작성 규칙서:
- 페르소나 의존 슬라이드의 표식: data.js 주석 `// [P]` (사례·생각해보기·과제 등 교체 대상). 이후 모든 콘텐츠 지시서가 이 태그를 사용.
- 오버라이드 작성 절차: 기본판에서 `[P]` 슬라이드 목록 추출 → 페르소나 사례로 재작성 → slidesVariants 등록 → 검증.
- 금지: 개념·도식·핵심 문장(big/quote) 슬라이드의 페르소나 분화(공유 자산 원칙).
- 페르소나 화자 명명 관례 기록: 직장인=김주임(기본), 대학생=박선배, 자영업=최사장 (추후 확정 시 갱신).

## ④ 파일럿 검증용 샘플 1건

- 01강의 김주임 사례 슬라이드 1장을 `student` 오버라이드 샘플로 작성(박선배: "AI 써본 적 없는데요" → 과제·팀플 맥락으로 동일 구조 치환) — **메커니즘 검증용이며, 정식 콘텐츠는 추후**. 검증 후 샘플은 남겨둠(가이드의 실례).

## ⑤ 검증

- [ ] 기본 URL: 완전히 기존과 동일(합성 로직이 기본판에 0 영향).
- [ ] `?variant=student`: 01강 해당 슬라이드만 박선배판, 나머지 전부 기본판 상속. HUD 'S' 뱃지. 세션 유지.
- [ ] 미등록 값(`?variant=xyz`): 조용히 기본판.
- [ ] 이어보기·핵심훑기·완료판정이 variant와 무관하게 동작(오버라이드로 big/quote가 바뀌면 훑기에 그 판이 반영되는지 확인).
- [ ] 텔레메트리에 variant 반영(코드 입장 시), 기존 이벤트 회귀 없음 → 테스트 데이터 정리.
- [ ] 콘솔 0건. 커밋 (예: "페르소나 variant 기반: 부분 오버라이드 + 레지스트리 + 작성 가이드").

## ⑥ 본진 이식 메모

- 완료 보고에 "본진 이식 대상" 명시: 이 구조가 slidesPersonal의 상위 호환이므로, 본진 이식 시 `slidesPersonal` → `slidesVariants.personal`로의 마이그레이션 경로를 한 단락으로 정리해 보고(실제 이식은 별도 지시).

## 가드레일

- 기본판 콘텐츠(로비 63장) 무변경(주석 `[P]` 태그 추가는 허용 — 렌더 무영향 확인). 본진 무변경.
- 엔진 수정은 합성 로직·플래그·뱃지에 한정. 판정·수집 로직 구조 변경 금지.
