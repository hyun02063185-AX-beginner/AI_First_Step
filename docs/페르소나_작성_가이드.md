> 「첫 출근」을 직장인판(기본) 외에 대학생·자영업자 등 페르소나별 사이드 버전으로 확장하는 기반.

## 1. 개념 — 부분 오버라이드 상속

페르소나판은 "바뀐 슬라이드만" 갖는다. 나머지는 기본판(직장인)을 그대로 상속한다.
기본판을 고치면 모든 페르소나에 자동 반영된다 — 유지보수 대상은 항상 기본판 + 오버라이드 몇 장뿐.

- **공유**: 개념 설명, 도식(`image`), 핵심 문장(`big`/`quote`) — 원칙적으로 페르소나 분화 **금지**.
- **교체 대상**: 사례(`사례 · ...`), 생각해보기, 한 장 정리+과제 — 화자·맥락이 사람마다 다른 슬라이드.

## 2. 데이터 구조

```js
lecture01: {
  id: 1, title: "...", tagline: "...",
  slides: [ /* 기본판(직장인) — 항상 완전한 정본, 페르소나 무관 렌더 가능 */ ],
  slidesVariants: {
    // 페르소나키: { 슬라이드인덱스(0-base): 완전한 슬라이드 객체 }
    student: { 6: { type: 'bullets', title: '...', subtitle: '...', items: [...] } }
  }
}
```

- **오버라이드 단위 = 슬라이드 "인덱스"(0-base)**, id 기반이 아니다. `js/main.js`의
  `resolveSlides(lecture)`가 `base.map((s, i) => overrideMap[i] || s)`로 합성한다.
- 오버라이드 값은 **완전한 슬라이드 객체**(타입 변경도 허용 — 예: bullets → split으로 바꿔도 됨).

### 왜 인덱스 방식인가 (id 방식 대신)

두 방식을 검토했다:

1. **인덱스 방식(채택)** — 슬라이드 배열의 위치로 오버라이드를 지정. 기존 슬라이드에 아무 필드도
   추가할 필요가 없다 — 이미 커밋된 로비 63장 등 기존 콘텐츠를 한 글자도 건드리지 않고 바로 오버라이드
   대상이 될 수 있다.
2. **id 방식(기각)** — 모든 슬라이드 객체에 `id: '...'`를 미리 부여해야 오버라이드가 가능. 안정적이지만
   기존 20강 전체(수백 장)에 소급 적용해야 실효성이 생기는데, 이는 "기본판 콘텐츠 무변경" 가드레일과
   충돌하고, 지금 규모(파일럿 1건)에 비해 과한 선투자다.

**트레이드오프**: 인덱스 방식은 기본판 슬라이드를 **중간에 삽입/삭제**하면 오버라이드 인덱스가 밀려
엉뚱한 슬라이드를 덮어쓸 수 있다. 그래서:

- 슬라이드 **추가/삭제는 이 시스템의 범위 밖**이다(교체만). 기본판 배열 길이를 바꾸는 수정을 하려면,
  그 강의의 `slidesVariants`를 함께 점검해 인덱스를 다시 맞출 것.
- 페르소나가 많아지거나(4개 이상) 콘텐츠가 자주 재배열되는 강의가 생기면, 그 강의에 한해
  `id` 기반으로 전환하는 것을 고려한다(전체 소급 적용이 아니라 필요한 강의만 opt-in).

## 3. 전환 로직 (엔진 — `js/main.js`)

- `?variant=<페르소나키>` — `SITE_CONFIG.personas`에 등록된 키면 활성화. 미등록 값은 조용히 기본판.
- `?variant=personal`은 예약어(기존 `slidesPersonal` 경험판 스위치) — 페르소나 키로 등록 불가.
- `location.search`는 해시 라우팅으로 건드려지지 않으므로 세션 동안 자연 유지. **localStorage에는
  저장하지 않는다** — 링크로만 제어(평소 배포 링크는 항상 기본판).
- `window.App.resolveSlides(lecture)`가 합성된 슬라이드 배열을 반환 — `js/slides.js`(렌더)와
  `js/main.js`의 `tocKeyLines`(핵심 훑기)가 모두 이 함수를 거친다.

## 4. 페르소나 레지스트리 (`js/site-config.js`)

```js
personas: {
  default: { label: '직장인', badge: null },
  student: { label: '대학생', badge: 'S' },
  owner:   { label: '자영업', badge: 'O' }
}
```

- 새 페르소나 추가 = 이 객체에 항목 하나 추가 + 해당 강의들의 `slidesVariants`에 키 추가.
- `badge`가 있으면 HUD 좌측에 작은 글자 뱃지로 표시(기존 "P"(경험판) 뱃지와 같은 관례 재사용,
  `.hud__vp` 클래스 공유 — CSS 추가 불필요).

## 5. `[P]` 태그 — 페르소나 의존 슬라이드 표식

`data.js`에서 사례·생각해보기·과제 등 **페르소나에 따라 갈아끼울 후보** 슬라이드에는 한 줄 주석을 단다:

```js
{ type: 'bullets', title: '사례 · ...',    // [P]
  subtitle: '...',
  items: [...] },
```

- 렌더에는 아무 영향 없다(순수 주석). 아직 오버라이드를 안 썼어도 "나중에 갈아끼울 후보"라는 표시로
  먼저 달아둘 수 있다.
- 이 태그가 붙었다고 반드시 오버라이드가 있어야 하는 건 아니다 — 우선순위 낮은 페르소나는 기본판을
  그대로 상속해도 무방(그게 이 시스템의 핵심 이점).
- **금지**: `big`/`quote`/`image`/개념 `bullets`에는 `[P]`를 달지 않는다(공유 자산 원칙 §1).

## 6. 오버라이드 작성 절차

1. 기본판에서 `[P]` 태그가 달린 슬라이드 목록을 추출한다.
2. 각 슬라이드를 페르소나 사례로 재작성 — **구조(타입·항목 수·서사 박자)는 최대한 유지**, 화자·맥락만
   치환. (예: "겁부터 났다 → 세어봤다 → 이미 쓰고 있었다 → 겁이 줄었다"의 4박자는 그대로, 인물·상황만
   바뀜.)
3. 해당 강의 객체에 `slidesVariants.<페르소나키>[인덱스] = {...}`로 등록한다.
4. 검증: `?variant=<키>`로 접속해 해당 슬라이드만 바뀌고 나머지는 기본판인지, 핵심 훑기·이어보기가
   정상인지 확인.

## 7. 페르소나 화자 명명 관례

| 페르소나 | 화자 | 맥락 |
|---|---|---|
| `default`(직장인) | 김주임 | 사무실·팀장·회사 업무 |
| `student`(대학생) | 박선배 | 강의실·교수님·과제·팀플 |
| `owner`(자영업) | 최사장 | 가게·손님·매출 |

(추후 확정 시 갱신 — 지금은 파일럿 1건 기준.)

## 8. 파일럿 샘플 (검증용)

`js/data.js` 01강(index 6, 사례 슬라이드)에 `student` 오버라이드 1건이 등록돼 있다 —
"저 AI 써본 적 없는데요"(김주임, 회사/팀장 맥락) → 박선배(대학생, 과제/팀플 맥락)로 같은 4박자 구조를
그대로 치환한 실례. 정식 페르소나 콘텐츠는 20강 완성 후 별도 지시서로 진행하며, 이 샘플은
메커니즘 검증 및 작성 예시로 남겨둔다.

## 본진 이식 메모

이 구조(`slidesVariants` + 인덱스 오버라이드)는 본진의 `slidesPersonal`(강의 전체를 통째로 바꾸는
방식)의 상위 호환이다. 본진 이식 시 마이그레이션 경로:

- 본진의 `lecture.slidesPersonal`(예: 7·8강의 14/16장 경험판)을
  `lecture.slidesVariants.personal = { 0: slide0, 1: slide1, ... }` 형태로 **전체 인덱스를 오버라이드**로
  등록하면 동일하게 동작한다(전체를 바꾸는 것도 부분 오버라이드의 극단적인 경우일 뿐).
- 단, 본진의 `?variant=personal`은 이 가이드의 페르소나 레지스트리와 별개로 예약어 취급되므로,
  실제 이식 시 `SITE_CONFIG.personas`에 `personal` 키를 추가하거나(레이블만 다르게), 기존
  `window.__variantPersonal` 특수 분기를 유지한 채 `slidesVariants` 합성 로직만 공유하는 두 가지
  선택지가 있다 — 실제 이식은 이 문서가 아니라 별도 지시서에서 결정.
